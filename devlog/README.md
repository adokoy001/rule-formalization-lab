## 書き方

意味のある作業の区切りで、その日のファイルへ追記する。日付は日本時間を基準にする。新しい日付のファイルを作ったら、上の一覧にも追加する。

必要な項目だけを使い、短い変更は数行でよい。

```markdown
## 作業名

- 目的:
- 変更・判断と理由:
- 確認: 実施した操作・テスト、結果、証拠へのリンク。
- 未解決:
- 次の一歩:
```

実装していない案を成果扱いしない。後から振り返って書いた記録は、その旨を明記する。コードや仕様の状態が変わったら、STATUS.mdも更新する。

記録を増やすために追加の実験や承認手順を設けない。実際に行ったことを残す。
